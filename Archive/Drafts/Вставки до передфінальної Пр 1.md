# Вставки та точкові заміни для передфінальної Пр 1

DOCX прочитано, але не змінено. Нижче — текст для перенесення замість відповідних фрагментів. Не потрібно додавати всю розширену чернетку.

## Перед ходом роботи

Перейменувати поточне «Завдання» на «Головна ідея». Перед ним повернути оригінальний текст:

**Завдання**

Розробити власний проєкт гейміфікації навчального курсу або окремої навчальної дисципліни. Проєкт має перетворити традиційний процес навчання на систему, у якій студент отримує бали, досягнення, рівні, нагороди або інші ігрові стимули за виконання навчальних завдань.

**Головна ідея**

SQL Post — навчальна гра про роботу у поштовому відділенні. Клієнт описує посилку, а гравець сам складає SQL-запит для її пошуку. Автоматичний preview показує результат під редактором; натискання єдиної кнопки Run відправляє робота за вибраними коробками. Грати можна самостійно або на навчальному занятті.

## Пункт 1 — уточнити результат навчання

Користувач самостійно складає DQL-запити для пошуку посилок, розуміє отриману вибірку та виправляє помилки. У першому рівні опановує SELECT, FROM, вибір стовпців і WHERE; наступні рівні поступово розширюють синтаксис.

## Пункт 2 — заповнити мотиваційні проблеми

Гейміфікація має зменшити чотири проблеми навчальної мотивації: втрату інтересу до одноманітних вправ, небажання повторювати вивчене, відсутність відчутного прогресу та зниження впевненості після помилок. Для цього гра використовує різні клієнтські замовлення, повторення у наступних рівнях, зірки й монети та безштрафний preview перед видачею. Це проєктні гіпотези, які перевірятимуться під час тестування.

## Пункт 3 — короткі уточнення

Першу ціль сформулювати однозначно: «Після рівня користувач самостійно виконує щонайменше 3 із 4 нових завдань на вивчений синтаксис». Перевірка — після проходження, без готового SQL; це відрізняється від повторення прикладу під час вступу.

Після таблиці додати: «Числові пороги є початковими цілями pilot test, а не вже досягнутими результатами».

## Пункт 4 — замінити останнє речення сюжету

Останній багатий клієнт описує свою посилку складніше, забирає знайдену роботом золоту коробку та щедро платить; правильна видача може також зарахувати додаткову місію.

## Пункт 5 — замінити таблицю із залишками шаблону

| Механіка | Правило та винагорода | Навіщо |
| --- | --- | --- |
| SQL-керування роботом | SQL за описом клієнта; Run запускає видачу | Видимий результат практики |
| Рівні | Новий синтаксис після 3★ | Поступове ускладнення |
| Колега-наставник | Показ на перших клієнтах, далі менше підказок | Легший початок практики |
| Автоматичний preview | Result set під редактором без штрафів | Самостійна перевірка SQL |
| Реакції та спроби | −5 за неправильну видачу; після третьої клієнт іде | Уважність до результату |
| Зірки | 0–3★ за основних клієнтів | Зрозумілий прогрес |
| Монети | +10 / +20 / +30 за складністю | Винагорода за кожен успіх |
| Досягнення | Badge за конкретну умову | Додаткові цілі |

Рейтинг, командні змагання та інші шаблонні рядки не описують погоджений single-player MVP. Майбутні місії та декор уже можна коротко згадати в системі нагород.

## Пункт 6 — уточнити правила

Preview оновлюється автоматично під час написання SQL й не витрачає спроб. Єдина кнопка Run відправляє робота за поточною вибіркою. Неправильна видача коштує 5 монет; після третьої клієнт іде. Синтаксичні помилки до видачі не штрафуються.

Рівень містить 13 клієнтів: 4 легкі, 4 середні, 4 на повторення та 1 бонусний останнім. На першому рівні повторюється матеріал вступу та попередніх замовлень. Максимум без штрафів: 4×10 + 4×20 + 4×10 + 30 = 190 монет.

| Зірки | Частка основних клієнтів | Кількість із 12 |
| --- | --- | --- |
| 0★ | Менше 50% | 0–5 |
| 1★ | Від 50% до менш ніж 80% | 6–9 |
| 2★ | Від 80% до менш ніж 100% | 10–11 |
| 3★ | 100% | 12 |

Бонусний клієнт не впливає на зірки. За його правильне обслуговування нараховуються 30 монет.

## Пункт 8 — виправити нагороду

Для «Золотої доставки» замінити умову на: «Правильно видати золоту коробку бонусному клієнту».

Необов’язкове речення, якщо дозволяє обсяг: «Після MVP планується декоративна нагорода з незатребуваної коробки після проходження трьох різних рівнів».

## Пункт 9 — дві точкові заміни

**Завдання:** «За підготовленими репліками 13 клієнтів складати SQL-запити для пошуку їхніх посилок: за номером, прізвищем або іншими вивченими ознаками».

**Критерії успішного проходження:** «Обслужити 12 основних клієнтів і отримати 3★. Бонусний клієнт необов’язковий для проходження. Засвоєння теми додатково перевіряється новими завданнями без готового SQL».

## Пункт 10 — опис прототипу

Основний екран: ліворуч склад, робот і клієнт; праворуч його репліка, схема таблиці, SQL-редактор, автоматичний preview під ним та одна кнопка Run. Верхня смуга містить профіль, рівень, прогрес обслуговування, зірки й монети. Окремі невеликі макети показують вибір рівня та підсумок із нагородами. Візуальний стиль — затишний pixel art із легкими sci-fi деталями та читабельним текстом інтерфейсу.

Вставити новий макет після його створення; поточний референс не містить усіх цих елементів.
