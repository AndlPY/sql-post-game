## Чинні рішення

### Платформа, UI та збереження

- Web, single-player, Windows у пріоритеті; desktop Chrome/Edge/Firefox — ціль перевірки, не гарантія. Full HD — design target, UI адаптується до звуження; mobile поза MVP.
- TypeScript + Phaser + HTML/CSS UI. Gameplay v3 — візуальна ціль; значні відхилення погоджувати. Тексти/кнопки справжні HTML; generated frames/atlases дозволені. Наявні scene assets повторно використовувати.
- PostgreSQL/PGlite у Web Worker; SQLite розглядати лише за суттєвої несумісності. Навчальна DB не має доступу до профілю. Один read-only SELECT, watchdog/recovery; не оголошувати неперевірені гарантії.
- GitHub Pages, repository sql-post-game; без платного domain/backend. Публікація після перевірок і прямого доручення; порядок у Development.
- Один локальний профіль: nickname, стать, монети, пройдені рівні/найкращі зірки. Немає Auth/cloud/multiple profiles. Storage version незалежна від release.
- Прогрес усередині зміни не зберігається; після входу початок заново. Монети зберігати після успішної видачі, best stars не зменшувати. Внутрішнє попередження виходу та beforeunload, коли browser дозволяє.
- Українські UI/репліки/імена; таблиці/поля англійською, кольори можуть бути англійською.
- Меню: 10 тем за пунктом 7 [game design](<Пр 1 .md>), playable рівні 1/2; майбутні теми недоступні. Наступний рівень за 3★ попереднього, не за монети. Профіль, монети, зірки, повернення з гри та підсумку.
- Gameplay: кнопка Меню першою зліва в HUD; Esc відкриває той самий діалог виходу, повторний Esc закриває його. Під час busy-операції вихід заблокований; відкриті діалоги зберігають свою поведінку Escape.
- Morning лише в меню, loop, mute/volume та збереження налаштувань; audio після взаємодії, autoplay може блокуватись.

### SQL, оплата та рівні

- Рівень 1: SELECT/FROM, поля, WHERE =; рівень 2: >, <, <> у нових завданнях, = та вибір полів у review. Єдиний склад src/data/parcels.ts для всіх рівнів; правильність за id, не еталонним SQL.
- 4 easy + 4 medium + 4 review + 1 bonus. Shuffle easy/medium; по 2 випадкові review в кожній половині, bonus останній. Клієнт 0 перший, окремий від 13, без монет/спроб/зірок. Review — попередній матеріал, не позиції 9–12. Деталі й авторство — [level-authoring](level-authoring.md).
- Дозволений SELECT з одним рядком і правильним id приймається, зокрема SELECT *. Нуль/множина/відсутній id — пояснення без руху, штрафу та витрати спроби. SQL error не штрафує. Неправильну одну коробку доставити й застосувати помилку.
- 3 помилки — клієнт іде неоплачений. Кожна помилка мінус 5 від потенційної оплати, floor 0; wallet не зменшується. Винагороди 10/20/30, максимум 190. Зірки за основних: 0–5 → 0★, 6–9 → 1★, 10–11 → 2★, 12 → 3★; bonus на зірки не впливає. Total /13, main /12 та bonus окремо.
- Репліки створюються автором за єдиним порядком у level-authoring: тема/складність → пошуковий SQL → ознаки й неоднозначність у спільному складі → природна репліка. Процедурна runtime-генерація не входить у цей етап. Автоматично додавати ім’я/прізвище або підказувати готовий id поза темою заборонено; імена можуть повторюватися. Дозволено два кроки: пошук → звірення ознак у preview → видача за знайденим id. Оператор не є умовою прийняття.
- Репліки природні, з достатніми ознаками одержувача; додаткові посилки не повинні робити завдання нерозв'язним. Не вимагати конкретних колонок у відповіді понад id. Бонус рівня 1: 2800 g → weight_kg 2.8, без ненавченого AND.
- SQL highlighting, автопари лапок; keyword autocomplete вимкнений. Доповнення таблиць/полів можливе пізніше.

### Сцена та tutorial

- Робот перевозить одну коробку; пояснити це в tutorial/UI. Не проїжджає крізь стіни/полиці, лише вільними проходами. Час руху ×2 від v0.1.0, уповільнення та паузи pickup/handoff; база/видача біля працівника, невірна коробка повертається.
- Полиці/фонові коробки не змінювати; pickup збоку/вдалині, віддзеркалення допустиме. Gold має стосуватися коробки, не всього робота.
- MVP: tan-hat, redhead, red-beret, brown-haired-man, glasses-bob; 2–3 у черзі, репліка/портрет синхронні. Вхід/вихід унизу окремими смугами, підхід близько 1–2 с. Оливковий варіант запасний; його sheet зараз відсутній, див. каталог.
- Перший повний UI-вступ лише раз у першому рівні: привітання, робота, клієнт/оплата, робот, Далі/Назад/Пропустити. Гра доступна під час пояснень.
- SQL-вступ при кожному новому запуску рівня; template містить тексти, цілі стрілок, demo та умови переходу. Наставник може вписати SQL, гравець натискає дії; жести/підсвічування/стрілки за DOM bounds, resize без перекриття click target.
- Demo — клієнт 0 до оцінюваних клієнтів. «Пояснення наставника» — безкоштовна коротка довідка без повторного demo; окремих підказок до кожного замовлення немає.

## SFX — після музики меню

1. Правильна видача — короткий приємний сигнал підтвердження.
2. Неправильна видача — м'який сигнал, без різкого покарання.
3. Run — коротке прийняття команди роботом.
4. Рух робота — дуже короткий механічний проїзд під 0,5–1 с доставки.
5. Захоплення / повернення коробки — невеликий механічний click.
6. Монети — коротка винагорода без довгої послідовності дзвону.
7. Завершення рівня й поява зірок.
8. UI click і відкриття панелі наставника.
9. Вхід/вихід клієнта, тихі кроки.
10. Особлива видача золотої коробки.
11. Ненав'язливий ambience поштового відділення.
12. Додаткова фонова музика — лише за потребою; Morning уже призначена для меню.

Після додавання: mute, окремі рівні music/SFX, збереження налаштувань, запуск audio після взаємодії користувача, не накладати дублікати при повторних подіях. Підготувати короткі файли та перевірити право використання.

## Анімації — деталі реалізації

1. **Натискання кнопки — UI.** Кнопка `Run` та інші кнопки коротко втискаються й повертаються у звичайний стан.
2. **Результат запиту — UI.** Коротка підсвітка успішного результату або легке похитування повідомлення про помилку.
3. **Поява пояснення — наставник і клієнти.** Портрет разом із текстовою панеллю плавно з’являється та зникає.
4. **Оновлення прогресу — HUD.** Смуга обслугованих клієнтів плавно заповнюється; лічильник монет коротко підсвічується після винагороди.
5. **Дихання — працівник, працівниця, наставник і клієнти в idle.** Ледь помітне підняття плечей і грудей; стопи залишаються на місці. Персонажі дихають несинхронно.
6. **Обертання коліс — робот під час руху.** Видимі колеса обертаються відповідно до швидкості та зупиняються разом із роботом; корпус залишається стабільним.
7. **Кліпання — люди в idle та їхні портрети.** Очі ненадовго заплющуються через нерівні проміжки часу; решта обличчя нерухома.
8. **Очікування — клієнти в черзі.** Зрідка трохи переносять вагу з ноги на ногу, залишаючись на своєму місці.
9. **Реакція екрана — робот.** Коротка зміна яскравості очей після отримання команди або захоплення посилки.
10. **Інерція вантажу — робот із посилкою.** На початку руху й під час зупинки руки та коробка ледь погойдуються разом, без ковзання коробки в захваті.

### Tutorial

11. **Підсвічування поточного UI-елемента.** М'який pulse рамки без блокування решти гри під час покрокового пояснення; усі елементи залишаються клікабельними. Кроки Далі/Назад/Пропустити керують підсвічуванням.
12. **Стрілки наставника.** Стрілка спрямована на елемент поточного кроку, перераховується при resize, не перекриває текст/click target.
13. **Портрети наставника.** Зміна підготовлених жестів між інструкціями UI та SQL; коротка поява панелі внизу екрана. Демонстраційний клієнт окремий, без монет.
